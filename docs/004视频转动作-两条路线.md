# 004. 真人视频 → 机器人动作:两条路线规划

> 目标:给定一段真人动作的 mp4,自动生成可在 `sim/panel.py` 里 ▶ 播放的 Motion JSON。
> 两条路线并行推进,先做工程化那条出 MVP,模型化那条作为长期方向。

---

## 0. 项目现状(我们已有的"家底")

| 资源 | 路径 / 文件 | 作用 |
|---|---|---|
| 机器人 URDF | `model/LingLong2.0/LingLong2.0.urdf` | 30 个 1-DOF 铰链,**无 free joint**(无浮动基座) |
| 运动学显示 | `sim/panel.py` | PyQt5 + MuJoCo,纯运动学(无物理仿真) |
| 动作数据格式 | `Motion { keyframes: [(t, pose)] }` + `sim/saved_motions/*.json` | 关键帧 + 线性插值,直接 ▶ 播放 |
| 关节字典 | `docs/003关节-视觉参考.md` | 30 个关节的"轴向语义" + 角度范围(给 VLM 当 prompt 用) |
| 校准图集 | `calibration/*.png` + `校准任务说明.md` | 关节值 → 视觉效果的 ground truth |

**关键约束**:
- 30 个关节,全身只能动 30 个独立角度
- 没有"骨盆 6DOF 自由",所以人走路的"全身平移"机器人复刻不了 — 现阶段**只复刻上半身 + 原地站姿**
- 没有物理引擎参与 → 关节角之间不需要考虑 ZMP/力矩平衡

---

## 1. 路线 A:工程化 (几何重定向) ⭐ 先做这条

### 1.1 思路

```
mp4 视频
  → MediaPipe / RTMPose 估出 33 个 3D 人体关键点
  → 把人体骨骼"重定向"到机器人骨骼(只取上半身)
  → 几何 IK 反解各关节角(肩 pitch/roll/yaw + 肘 + 腕)
  → 限位 + 平滑 + 降采样 → Motion JSON
  → 喂给 panel.py ▶ 播放
```

**所有步骤纯 Python + CPU,无 GPU,无训练,无网络。**

### 1.2 技术栈

| 阶段 | 工具 | 理由 |
|---|---|---|
| 视频解码 | `opencv-python` | 现成 |
| 2D/3D 关键点 | `mediapipe` (Tasks API) | CPU 实时,30fps 无压力;`mp_pose` 直接出 33 点 |
| 3D 备选 | `rtmlib` + RTMPose | 精度高,纯 PyTorch CPU 也跑得动 |
| 几何 IK | `numpy` 手写(~100 行) | 30 关节手算够用,不必上 `ikpy`/`pinocchio` |
| 平滑 | `scipy.signal.savgol_filter` | 业界标准关节角平滑 |
| 限位 | `model.jnt_range` | 直接用 MuJoCo 的关节范围表 |
| 输出 | 自写 `Motion` dataclass | 直接复用 panel.py 的 `Motion/Keyframe` |

### 1.3 骨骼重定向映射(MediaPipe → 机器人)

| MediaPipe 关键点 | 机器人关节链 |
|---|---|
| 11/12(左右肩) → 13/14(左右肘) → 15/16(左右腕) | L/R_shoulder_pitch, L/R_shoulder_roll, L/R_shoulder_yaw, L/R_elbow, L/R_wrist_* |
| 0(鼻) → 11/12(肩中点) | head_yaw, head_pitch(从躯干倾角推) |
| 11/12 + 23/24(髋) 中点连线 | waist_yaw, waist_pitch(从躯干倾角推) |
| 23/24(髋) → 25/26(膝) → 27/28(踝) | L/R_hip_*, L/R_knee, L/R_ankle_* |

> 髋/膝/踝 这块当前阶段**先不做**(机器人没有浮动基座,下半身角度没意义,会让人走路看起来像"踩缝纫机")。
> 1.0 版本**只动上半身**(头 + 腰 + 双臂)。

### 1.4 阶段拆解

| 阶段 | 产出 | 估时 | 完成度 |
|---|---|---|---|
| **A0**: 视频→关键点 JSON | `tools/pose_extract.py` 输出 `out/<video>.pose.json` | 0.5 天 | ⬜ |
| **A1**: 骨骼重定向 + 几何 IK | `tools/retarget.py` 输入 pose.json,输出 joint angle 序列 | 1 天 | ⬜ |
| **A2**: 限位 + 平滑 + 关键帧采样 | 同一脚本内,降采样到 5~10 fps,写 `Motion` JSON | 0.5 天 | ⬜ |
| **A3**: 接入 panel.py | 新增"📥 导入视频"按钮,跑 A0~A2 pipeline 后直接 ▶  | 0.5 天 | ⬜ |
| **A4**: 真实视频试错 + 调参 | 拿 3~5 段真人视频(挥手/鞠躬/舞蹈)打磨效果 | 1~2 天 | ⬜ |
| **A5**: 兜底:手调微调 | panel.py 加"加载视频生成的 pose 后,允许单关节微调后另存" | 0.5 天 | ⬜ |

**MVP 定义 (A0~A2)**: 跑通 `python tools/retarget.py xxx.mp4` 出一个 `xxx.motion.json`,在 panel.py 里能播,姿态"像"原视频(不需要逐帧对齐)。

### 1.5 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| MediaPipe 单目 3D 精度差 | 侧身/遮挡时关节角抖 | 改用 RTMPose;对输出做 Savitzky-Golay 平滑(窗口 11) |
| 比例/坐标系不匹配 | 机器人和人动作"幅度不对" | 录一段"校准 T-pose"视频,先算两套骨架的尺度缩放,再 IK |
| 肘关节反关节 | MediaPipe 给的肘角 > 180° 时机器人卡限位 | 后处理:用 `atan2` 把肘角夹到 (0, π) |
| 站立不稳 | 机器人下半身的零位被 MediaPipe 误推 | MVP 阶段下半身**直接锁为 T-pose**,只动上半身 |
| 多人/遮挡 | 框错人 | MediaPipe `min_detection_confidence` ≥ 0.5,只取最大框 |

### 1.6 验收标准

- [ ] 输入 30 秒挥手视频,输出 JSON 能在 panel.py 播放
- [ ] 视觉效果: 10 个观察者里 ≥ 7 个说"是挥手"(盲测,不给原文)
- [ ] 关节角无超限、无突变、无 NaN
- [ ] 处理时间: 30 秒视频 < 30 秒(实时或更快)

## 2. 路线 B:模型化 (端到端) — 长期方向

### 2.1 思路

```
mp4 视频
  → 视觉编码器(ViT/VideoMAE) 提特征
  → 时序解码器(Transformer/Diffusion) 直接出 30 维 joint trajectory
  → 限位 + 平滑 → Motion JSON
  → 喂给 panel.py ▶ 播放
```

或更现实的子路线:

```
mp4 视频
  → 预训练 VLM(Claude / GPT-4V / InternVideo2) 看关键帧
  → 输出"动作描述 + 关键关节角"
  → panel.py 用关键帧 + 线性插值播放
```

### 2.2 三种子路线对比

| 子路线 | 代表工作 | 硬件需求 | 数据需求 | 效果上限 | 移植到你机器人 |
|---|---|---|---|---|---|
| **B1**: 端到端 Video→Joint | HOMIE (CoRL 2024)、Vid2RobotPro | 8× A100 训练 | 百万级视频-动作对 | 高 | 难(论文绑死 H1) |
| **B2**: SMPL 中间表示 + Retarget | GMR、HMR2.0+robot-retargeting | 1× GPU 推理 | 用现成 SMPL 预训练模型 | 中-高 | 中(改 retarget 映射) |
| **B3**: VLM 当"动作描述器" | Claude/GPT-4V + 我们的关节表 | 0(API 调用) | 0(纯 prompt) | 中(复杂动作不可靠) | 易(零代码集成) |

**短期只做 B3**(0 成本可玩);B1/B2 作为未来能力扩展。

### 2.3 B3 阶段拆解(VLM 路线,可立刻启动)

| 阶段 | 产出 | 估时 | 完成度 |
|---|---|---|---|
| **B3-0**: 写好 prompt 模板 | `tools/vlm_motion.py`,输入 1 张图 + `003关节-视觉参考.md`,输出 JSON | 0.5 天 | ⬜ |
| **B3-1**: 多帧采样 | 1 段视频 → 抽 5~10 关键帧 → 每帧问 VLM → 拼接成 Motion | 0.5 天 | ⬜ |
| **B3-2**: 限位 + 平滑 | VLM 输出经常超界/抖动,做后处理 | 0.5 天 | ⬜ |
| **B3-3**: 与 A 路线对比 | 拿同一段视频,看 A vs B3 谁更像 | 1 天 | ⬜ |

### 2.4 B1/B2 长期阶段(暂不启动,记录占位)

| 阶段 | 产出 | 估时 | 启动条件 |
|---|---|---|---|
| **B1-0**: 调研 | 找 LingLong 2.0 或类似 30-DOF 机器人的 retarget 脚本(GMR、宇树官方) | 1 天 | B3 跑通且不满足 |
| **B1-1**: 装 SMPLer-X,跑出 mesh | 1× GPU 环境 | 1 天 | 有 GPU 机器 |
| **B1-2**: 写 retarget mapping | SMPL joints → 机器人 30 关节 | 2~3 天 | B1-1 成功 |
| **B1-3**: 训练/微调 | HOMIE-style 训练(如果数据不足) | 1 周 | 有数据 |

### 2.5 风险与对策

| 风险 | 对策 |
|---|---|
| B1/B2 论文绑死特定机器人 | 选 GMR(支持自定义 URDF)作为基础;要重写 retarget 逻辑 |
| SMPL 模型下载体积 5+ GB | 接受;放 LFS;一次性成本 |
| VLM 输出不可重复 | 多帧采样 + 投票 + 限位后处理 |
| VLM 不懂"关节角" | prompt 严格用 `003关节-视觉参考.md` 的范围表作为硬约束 |
| 端到端模型在你机器人上效果差 | 退回 A 路线,只用 B 做"自动命名"和"分段" |

### 2.6 验收标准(B3)

- [ ] 拿 1 张静态图,VLM 能输出 30 个合规关节角
- [ ] 拿 1 段 5 秒视频,10 个关键帧拼接后能播
- [ ] 视觉效果: 跟 A 路线对比,盲测胜率 ≥ 40%(因为 VLM 本来就是辅助)
- [ ] 单帧 API 调用 < 3 秒(Claude 4.x 实测约 1.5 秒)

## 3. 两条路线的边界与协同

| 维度 | 路线 A (工程化) | 路线 B (模型化) |
|---|---|---|
| **定位** | 主力,出 80% 可用动作 | 辅助,补 A 搞不定的复杂动作 |
| **依赖** | MediaPipe + numpy,CPU 即可 | VLM API 或 GPU 模型 |
| **可控性** | 高(每一步可解释) | 低(黑盒) |
| **维护成本** | 中(关节映射要校准) | 低(API 调用) |
| **天花板** | 单目 3D 精度上限 | 模型能力上限 |
| **何时切换到 B** | A 出现"光学遮挡/复杂舞蹈"搞不定时 | — |
| **数据回流** | 用 A 的输出当 B 的训练/微调数据(若有 GPU) | — |

**最终产品形态**:
```
panel.py 上多一个"📥 视频转动作"按钮
  → 弹窗让用户选 mp4
  → 后台跑 A pipeline(默认 5~10 秒出结果)
  → 若 A 置信度低(关键点缺失/抖动大),自动问 VLM(B3 路线)补帧
  → 用户在 panel 里 ▶ 预览,不满意就手动微调后另存
```
